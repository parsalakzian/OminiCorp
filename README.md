# OminiCorp — وب‌سایت معرفی خدمات

صفحهٔ فارسی در `/` و انگلیسی در `/en.html`. کاتالوگ، راهنمای انتخاب، نمایشگر دفتر، تماس مستقیم، فرم درخواست پروژه و عضویت خبرنامه. فونت‌ها، تصویر، استایل و اسکریپت‌ها محلی‌اند. لینک‌های تماس فقط پس از انتخاب کاربر به سرویس خارجی می‌روند.


وبلاگ فارسی `/blog` و انگلیسی `/en/blog`؛ پنل `/admin`؛ نقشهٔ خودکار صفحه‌ها و تصاویر `/sitemap.xml`. مدیریت مقاله، دسته‌بندی و آپلود تصویر در پنل، سئو، RSS/Atom، AI با پراکسی، زمان‌بندی و MCP در [راهنمای وبلاگ](docs/blog.md) آمده‌اند. Pages فقط مقاله‌های آغازین را ارائه می‌دهد و قابلیت‌های پویا روی کانتینر فعال می‌شوند.

## راه‌اندازی

با Docker و افزونهٔ Compose اجرا کنید؛ هیچ فایل `.env` یا تنظیم محیطی لازم نیست:

```sh
docker compose up -d --wait
docker compose exec website node server/setup.mjs
```

فرمان دوم یک کد یک‌بارمصرف می‌دهد که ۱۵ دقیقه اعتبار دارد. در `http://localhost:8080/admin/setup` (یا روی دامنهٔ HTTPS سایت) کد، نشانی عمومی و رمز دلخواه حداقل ۱۶ کاراکتری را وارد کنید. سپس در `/admin` وارد شوید. بدون کدِ میزبان کسی نمی‌تواند اولین حساب را بسازد. برای تغییر رمز، از «تنظیمات سایت ← عمومی و حساب» رمز فعلی را تأیید کنید؛ بعد از تغییر موفق همهٔ نشست‌ها بسته می‌شوند.

سایت `http://localhost:8080` و سلامت وب‌سرور `http://localhost:8080/healthz`. پورت میزبان و تگ ایمیج تنظیمات خود Docker هستند؛ اگر لازم است، آن‌ها را مستقیماً در `compose.yaml` تغییر دهید. برای استقرار عمومی، اتصال به `127.0.0.1` را نگه دارید و روی reverse proxy، HTTPS و حفظ هدر `Host` را تنظیم کنید. اگر بستهٔ GHCR خصوصی است، میزبان باید از قبل به آن دسترسی داشته باشد.

### فعال‌سازی فرم‌ها و SMTP

در `/admin/system` گزینهٔ «فعال‌کردن فرم‌های ایمیلی» را روشن و میزبان SMTP، پورت، امنیت و اطلاعات فرستنده/گیرنده را وارد کنید. پیش‌فرض پورت STARTTLS برابر `587` و TLS مستقیم `465` است. حالت بدون TLS فقط بدون احراز هویت و روی localhost مجاز است. اگر تنظیمات احراز هویت ندارید، نام کاربری را خالی و برای حذف رمز قبلی، گزینهٔ پاک‌کردن را انتخاب کنید. تغییر تنظیمات نیازی به restart ندارد.

فرم پروژه پیام را به صندوق تیم می‌فرستد و `Reply-To` را روی ایمیل کاربر می‌گذارد؛ متن درخواست در سرور سایت ذخیره نمی‌شود. «ارسال شد» یعنی SMTP دریافت را پذیرفته، نه تضمین رسیدن ایمیل به Inbox. از فرستندهٔ تأییدشدهٔ سرویس و تنظیمات SPF/DKIM سرویس استفاده کنید.

خبرنامه بعد از رضایت کاربر، لینک تأیید ۴۸ساعته و لینک لغو می‌فرستد. برای فهرست **فقط اعضای تأییدشده**:

```sh
(umask 077; docker compose exec -T website node server/export.mjs > subscribers.txt)
```

ارسال کمپین گروهی یا پنل مدیریت جزو این نسخه نیست. برای کمپین‌ها از سرویس ارسال خبرنامه با مدیریت لغو عضویت استفاده کنید و خروجی را محرمانه نگه دارید. محدودیت ارسال درون فرایند براساس آی‌پی سوکت است، به هدرهای ارسالی اعتماد نمی‌کند و پشت یک پراکسی همهٔ کاربران ممکن است یک سهمیهٔ مشترک داشته باشند. در استقرار پرترافیک، محدودیت‌های لبه را در reverse proxy تنظیم کنید. query string مسیرهای `/opt-in` و `/opt-out` نباید در لاگ پراکسی ذخیره شود.

**GitHub Pages استاتیک است**؛ صفحات و TV در آن کار می‌کنند، اما فرم‌ها فقط روی نسخهٔ Docker یا همان سرور Node فعال می‌شوند. اگر دامنه هنوز به Pages اشاره می‌کند، برای فعال‌کردن فرم‌ها آن را به reverse proxy کانتینر منتقل کنید. `/healthz` سلامت HTTP را بررسی می‌کند، نه اتصال SMTP؛ پس از تنظیم، یک درخواست و یک عضویت آزمایشی با ایمیل خودتان ارسال کنید.

### نمایشگر تلویزیون

روی تلویزیون `/?tv=1` را در فارسی یا `/en.html?tv=1` را در انگلیسی باز کنید. پخش خودکار بعد از بازکردن لینک شروع می‌شود. با دکمهٔ «تمام‌صفحه» از مرورگر وارد تمام‌صفحه شوید. کلیدهای جهت‌نما اسلاید را عوض و پخش خودکار را متوقف می‌کنند. اگر مرورگر مجاز بداند، هنگام پخش درخواست Screen Wake Lock می‌شود؛ برای نصب دائمی، تنظیمات خاموش‌شدن و حالت kiosk دستگاه را هم بررسی کنید. در مرورگرهای با گزینهٔ کاهش حرکت، انیمیشن‌ها خاموش می‌شوند و عوض‌شدن اسلاید ادامه دارد.

### اجرا بدون دانلود

پس از دریافت ایمیج، کانتینر هیچ وابستگی نصب نمی‌کند. روی میزبان آفلاین فقط SMTP از کار می‌افتد، مگر اینکه سرور ایمیل از شبکهٔ داخلی در دسترس باشد. برای انتقال آفلاین، نوع پلتفرم AMD64 یا ARM64 را متناسب با مقصد انتخاب کنید:

```sh
IMAGE=ghcr.io/parsalakzian/ominicorp:latest
docker pull --platform linux/amd64 "$IMAGE"
docker save -o ominicorp.tar "$IMAGE"
# روی مقصد، پس از انتقال فایل و compose.yaml:
docker load -i ominicorp.tar
docker compose up -d --pull never --wait
```

در ساخت نخست از سورس، مرحلهٔ build برای دریافت تصویر پایه و وابستگی‌های وب‌سرور به رجیستری‌ها نیاز دارد: `docker build -t ghcr.io/parsalakzian/ominicorp:latest .` و سپس `docker compose up -d --pull never --wait`.

## توسعه، تست و انتشار

```sh
npm ci                         # Node.js 24 پیشنهاد می‌شود
npm run dev                    # http://localhost:4173
npm run build                  # بازسازی هر دو HTML پس از تغییر منبع
npm test
npx playwright install chromium
npm run test:browser
```

برای کد راه‌اندازی محلی پس از اجرای سرویس: `node server/setup.mjs`. ساختار پروژه در [سند معماری](docs/architecture.md) و قرارداد فرم‌ها در [مستند API](docs/api.md) است. فونت‌های Vazirmatn و Space Grotesk از Fontsource نسخهٔ `5.3.0` با مجوزهای مربوط در `assets/fonts/` هستند.

گردش‌کار [GitHub Actions](.github/workflows/publish.yml) تست‌های منطق، تحویل آزمایشی SMTP، تست Chromium و smoke test کانتینر را اجرا می‌کند. پس از موفقیت، برای `main` تگ `latest` و برای شاخهٔ تحویل تگ `preview` ساخته می‌شود. تگ `sha-<commit>` هم برای هر دو پلتفرم `linux/amd64` و `linux/arm64` منتشر می‌شود. برای به‌روزرسانی `docker compose pull && docker compose up -d --wait`. لاگ‌ها `docker compose logs -f website`؛ برای بازگشت، تگ ایمیج را در `compose.yaml` به تگ SHA قبلی تغییر دهید. مسیرهای قدیمی `omixy` و `*.text` در مخزن دست‌نخورده‌اند و در کانتینر سرو نمی‌شوند.

### پشتیبان‌گیری و بازیابی خبرنامه

SQLite در volume `subscribers` است. از `docker compose down -v` استفاده نکنید مگر قصد حذف اطلاعات را دارید. پس از یک توقف تمیز، پایگاه بسته می‌شود و می‌توان فایل را برداشت:

```sh
umask 077
docker compose stop website
docker compose cp website:/app/data/subscribers.sqlite ./subscribers.backup.sqlite
chmod 600 ./subscribers.backup.sqlite
docker compose up -d --wait
```

برای بازیابی، اول از دیتابیس فعلی نسخه بگیرید، سرویس را متوقف کنید و با همان کاربر کانتینر فایل را در volume بنویسید:

```sh
docker compose stop website
docker compose run --rm --no-deps -T website sh -c 'umask 077; cat > /app/data/restore.tmp && rm -f /app/data/subscribers.sqlite-wal /app/data/subscribers.sqlite-shm && mv /app/data/restore.tmp /app/data/subscribers.sqlite' < subscribers.backup.sqlite
docker compose up -d --wait
```

### ارتقا از نسخهٔ فایل محیطی

مقاله‌ها، تنظیمات تحریریه و فهرست مشترکان باقی می‌مانند. در ارتقا، اولین مالک را با کد یک‌بارمصرف بسازید و دامنه و مقادیر SMTP/AI/MCP و پراکسی نسخهٔ قبلی را از پنل تنظیم کنید (برای MCP توکن تصادفی بسازید و کلاینت را به‌روزرسانی کنید)؛ مقادیر فایل‌های قدیمی خودکار خوانده نمی‌شوند. فایل‌های قدیمی را بعد از انتقال امن حذف کنید. `blog.sqlite` شامل حساب و تنظیمات سرویس‌هاست: فقط دسترسی مدیر میزبان، مجوز فایل محدود و پشتیبان رمزگذاری‌شده داشته باشید. رمز ادمین و توکن MCP هش می‌شوند؛ کلیدهای عملیاتی که برنامه باید به سرویس‌های خارجی بفرستد در پایگاه با دسترسی محدود نگهداری می‌شوند و از پنل بازخوانی نمی‌شوند.
