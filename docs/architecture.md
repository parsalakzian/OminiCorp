# معماری و نقشهٔ پروژه

## تصمیم قبل از پیاده‌سازی

این سایت کاتالوگ خدمات و نقطهٔ شروع تماس است، نه سامانهٔ ثبت سفارش. دو صفحهٔ HTML کامل برای سئو، دسترسی بدون جاوااسکریپت و سازگاری با مسیرهای فعلی کافی‌اند. یک مولد کوچک با Node استاندارد، محتوای هر دو زبان را در قالب مشترک قرار می‌دهد. تعامل‌ها در مرورگر و با progressive enhancement اجرا می‌شوند. در نسخهٔ پایه داده‌ای جمع‌آوری نمی‌شد. شیوهٔ اضافه‌شدن فرم‌ها و ذخیرهٔ عضویت در بخش توسعه شرح داده شده است. لینک‌های تماس، پس از انتخاب کاربر، به برنامه‌های خارجی هدایت می‌کنند؛ صفحه در بارگذاری هیچ CDN یا سرویس خارجی را فراخوانی نمی‌کند.

## توسعهٔ SMTP و نمایشگر

صفحات همچنان قابل میزبانی استاتیک هستند؛ فقط فرم‌ها به API هم‌مبدأ روی کانتینر نیاز دارند. وب‌سرور Node همان فایل‌های مجاز HTML/CSS/JS را سرو می‌کند و `/api/` را به لایهٔ فرم‌ها می‌دهد. درخواست پروژه فقط به ایمیل تیم ارسال می‌شود. SQLite فقط برای عضویت تأییدشده/منتظر تأیید و توکن‌های هش‌شدهٔ خبرنامه، در حجم پایدار Docker استفاده می‌شود. تأیید و لغو با POST انجام می‌شوند تا بازخوانی خودکار لینک ایمیل تغییری ایجاد نکند. خبرنامه در این نسخه شامل ثبت عضویت و خروجی فهرست است، نه ارسال دسته‌جمعی کمپین.

### رسانهٔ تحریریه

- `server/blog/media.mjs`: قرارداد مسیر، محدودیت اندازه و قالب، اعتبارسنجی فایل و Base64 و پاسخ HTTP تصویر؛ بدون دانلود تصاویر خارجی.
- `server/blog/markdown.mjs`: Markdown بدون HTML خام، رندر تصاویر داخلی و استخراج ارجاع‌های همان تصاویر برای ذخیره‌سازی.
- `server/blog/store.mjs`: مهاجرت SQLite، ذخیرهٔ فایل و نگاشت مقاله/تصویر؛ ارجاع‌ها هم‌زمان با مقاله در یک تراکنش به‌روزرسانی می‌شوند.
- `server/blog/{routes,admin,render,mcp}.mjs` و `assets/blog-admin.mjs`: مدیریت مقاله، کتابخانه و بارگذاری، رندر جلد و تصاویر متن، و ابزارهای MCP با همان قواعد ذخیره‌سازی.

### دسته‌بندی و ناوبری مجله

- `server/blog/categories.mjs`: قرارداد دستهٔ دوزبانه، تم‌های محدود و دسته‌های اولیهٔ مشترک با خروجی ایستا.
- `server/blog/store.mjs`: مهاجرت دسته‌ها، شناسهٔ ثابت، محافظت از ارتباط مقاله‌ها و شمارش استفادهٔ عمومی/داخلی.
- `server/blog/pagination.mjs`: کنترل شمارهٔ صفحهٔ مشترک پنل و مجله با نشانی‌های ساخته‌شده از فیلترهای معتبر.
- `server/blog/{admin,routes,render,mcp,automation}.mjs`: مدیریت دسته، مرور عمومی، دسترسی MCP و انتخاب دسته از فهرست واقعی در تولید AI.
- `site/export-blog.mjs`: ساخت صفحهٔ مستقل دسته‌های اولیه برای نسخهٔ ایستا؛ تغییرات پنل فقط در استقرار پویا نمایش داده می‌شوند.

### ورود تصویر به MCP

`server/blog/media-import.mjs` دریافت مستقیم HTTPS را با زمان/اندازهٔ محدود و بررسی و تثبیت نشانی عمومی در هر تغییرمسیر انجام می‌دهد. `mcp-http.mjs` مسیر باینری، احراز هویت و سقف هم‌زمانی را مدیریت می‌کند. ابزار MCP و مسیر HTTP هر دو از اعتبارسنجی و ذخیره‌سازی یکسان `media.mjs` و `store.mjs` استفاده می‌کنند.

### انتقال Streamable HTTP در MCP

`mcp-http.mjs` احراز هویت، مذاکرهٔ نوع پاسخ HTTP و بررسی اندازهٔ بدنه را انجام می‌دهد. `mcp.mjs` برای هر درخواست با SDK رسمی یک transport بدون session می‌سازد؛ JSON-RPC برای کلاینت‌هایی که SSE را صریحاً اعلام می‌کنند، در صورت اولویت یا تساوی با JSON، روی SSE ارسال می‌شود. نبود Accept یا wildcard (`curl`) پاسخ JSON مستقیم دارد. در درخواست داخلی به SDK هر دو نوع اعلام و پاسخ با backpressure به Node HTTP منتقل می‌شود؛ احراز هویت همچنان پیش از همین مرحله است. رویداد پیشرفت هر بارگذاری همراه همان پاسخ ارسال می‌شود؛ سرور stream دائمی، session یا replay نگه نمی‌دارد. مسیر باینری رسانه و قرارداد ابزارها مستقل می‌مانند.

### صفحهٔ اصلی و نقشهٔ سایت خودکار

- `server/blog/home.mjs`: بخش SSR نوشته‌های تازه به‌همراه قرارداد تعداد نوشته‌ها و تصاویر اصلی صفحه؛ مشترک بین خروجی ایستا و پاسخ پویا.
- `server/blog/sitemap.mjs`: ساخت نقشهٔ XML دوزبانه از URLهای canonical، صفحه‌بندی و تصاویر عمومی، با دادهٔ فعلی SQLite یا محتوای آغازین خروجی Pages.
- `site/render.mjs` قالب مشترک صفحهٔ اصلی را می‌سازد؛ سرور آن را با آخرین مقاله‌های منتشرشده اجرا می‌کند، و `site/build.mjs` نسخهٔ ایستا را با محتوای آغازین می‌سازد.

### متادیتا و تحویل صفحات عمومی

- `server/seo.mjs`: قالب مشترک canonical، hreflang، Open Graph، X Cards، آیکون و JSON-LD برای صفحهٔ اصلی و مجله.
- `server/public-response.mjs`: مذاکرهٔ gzip برای پاسخ عمومی و ساخت CSP مبتنی بر هش برای JSON-LD؛ مسیرهای خصوصی و MCP از فشرده‌سازی خارج‌اند.
- `server/blog/image-markup.mjs`: ویژگی‌های اندازهٔ تصویر با ابعاد فایل محلی یا متادیتای SQLite؛ بدون دانلود تصویر خارجی هنگام رندر.
- `site/build.mjs`: تولید یک stylesheet محلی برای صفحهٔ اصلی از CSS پایه، فرم‌ها و TV؛ SSR همان فایل را استفاده می‌کند. HSTS در پراکسی خاتمه‌دهندهٔ TLS فعال می‌شود (راهنمای `docs/seo.md`).
