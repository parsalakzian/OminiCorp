# معماری و نقشهٔ پروژه

## تصمیم قبل از پیاده‌سازی

این سایت کاتالوگ خدمات و نقطهٔ شروع تماس است، نه سامانهٔ ثبت سفارش. دو صفحهٔ HTML کامل برای سئو، دسترسی بدون جاوااسکریپت و سازگاری با مسیرهای فعلی کافی‌اند. یک مولد کوچک با Node استاندارد، محتوای هر دو زبان را در قالب مشترک قرار می‌دهد. تعامل‌ها در مرورگر و با progressive enhancement اجرا می‌شوند. در نسخهٔ پایه داده‌ای جمع‌آوری نمی‌شد. شیوهٔ اضافه‌شدن فرم‌ها و ذخیرهٔ عضویت در بخش توسعه شرح داده شده است. لینک‌های تماس، پس از انتخاب کاربر، به برنامه‌های خارجی هدایت می‌کنند؛ صفحه در بارگذاری هیچ CDN یا سرویس خارجی را فراخوانی نمی‌کند.

نمونه‌کار، اعضای تیم و آمار فاقد تأیید از نسخهٔ بازطراحی‌شده حذف می‌شوند. برای اضافه‌کردن محتوای واقعی، فقط منبع محتوا و در صورت نیاز بخش مربوط از قالب تغییر می‌کند.

## توسعهٔ SMTP و نمایشگر

صفحات همچنان قابل میزبانی استاتیک هستند؛ فقط فرم‌ها به API هم‌مبدأ روی کانتینر نیاز دارند. وب‌سرور Node همان فایل‌های مجاز HTML/CSS/JS را سرو می‌کند و `/api/` را به لایهٔ فرم‌ها می‌دهد. درخواست پروژه فقط به ایمیل تیم ارسال می‌شود. SQLite فقط برای عضویت تأییدشده/منتظر تأیید و توکن‌های هش‌شدهٔ خبرنامه، در حجم پایدار Docker استفاده می‌شود. تأیید و لغو با POST انجام می‌شوند تا بازخوانی خودکار لینک ایمیل تغییری ایجاد نکند. خبرنامه در این نسخه شامل ثبت عضویت و خروجی فهرست است، نه ارسال دسته‌جمعی کمپین.

| مسیر جدید | مسئولیت |
|---|---|

| `server/subscribers.mjs`, `server/export.mjs` | ذخیرهٔ پایدار، migration نسخهٔ SQLite، فهرست خروجی فقط از CLI |
| `site/forms.mjs`, `assets/forms.mjs`, `assets/forms.css` | متن و قالب فرم‌ها، وضعیت ارسال و طراحی فرم |
| `assets/tv.mjs`, `assets/tv.css` | پخش، تمام‌صفحه، بیدار ماندن نمایشگر و انیمیشن‌های TV |
| `tests/server.test.mjs` | تست HTTP، مرور عضویت و تحویل به SMTP محلی آزمایشی |
| `server/installation.mjs`, `server/setup.mjs` | اعتبارسنجی و احراز هویت میزبان برای راه‌اندازی یک‌بارمصرف |
