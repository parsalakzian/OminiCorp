# سئو، پیش‌نمایش اشتراک‌گذاری و استقرار HTTPS

- صفحهٔ اصلی، فهرست مجله، دسته‌ها و مقاله‌ها از عنوان و توضیح متناسب با صفحه و زبان خود استفاده می‌کنند. `canonical` و `hreflang` از نشانی عمومی ثبت‌شده در تنظیمات سایت ساخته می‌شوند. در مقاله عنوان و توضیح سئو و کاور را از ویرایشگر تعیین کنید؛ اگر کاور نباشد از تصویر پیش‌فرض مجله استفاده می‌شود. برای بهترین سازگاری با سرویس‌های اشتراک‌گذاری، کاور عمومی JPEG یا PNG با نسبت نزدیک به `1.91:1` پیشنهاد می‌شود. بعضی شبکه‌ها پیش‌نمایش قبلی را کش می‌کنند یا برای تصویر خارجی محدودیت خودشان را دارند.
- صفحهٔ اصلی `Organization`، `WebSite`، `WebPage` و خدمات واقعی را توصیف می‌کند. فهرست و دسته‌ها `CollectionPage` و در صورت وجود مطالب `ItemList`، و مقاله‌ها `BlogPosting` و مسیر راهنما دارند. محصول، رتبه‌بندی مشتری یا FAQ ناموجود به اسکیما اضافه نشده است. اسکیما تضمین نمایش Rich Result نیست.
- برای تصاویر تزئینی یا تکراری، `alt=""` عمدی است تا صفحه‌خوان متن را دوباره نخواند. برای کاور معنادار و تصاویر متن، توضیح مناسب هر زبان را در ویرایشگر وارد کنید. ابعاد فایل‌های خود سایت و تصاویر آپلودشده مشخص‌اند. برای کاور HTTPS خارجی، بدون واکشی از سرور دیگر ابعاد ذاتی قابل اتکا نیست؛ قاب CSS از جابه‌جایی چیدمان جلوگیری می‌کند. برای ابعاد دقیق، تصویر را در کتابخانه بارگذاری کنید.
- صفحهٔ اصلی به‌جای سه درخواست CSS مسدودکننده، یک استایل محلی دارد. استایل لازم برای چیدمان اولیه همچنان معمولی بارگذاری می‌شود تا فلش محتوای بدون استایل یا خرابی نسخهٔ بدون جاوااسکریپت رخ ندهد. عدد CLS یا LCP تولید باید روی دامنهٔ واقعی اندازه‌گیری شود.
- AMP برای ایندکس یا رتبه‌بندی لازم نیست. نسخهٔ واکنش‌گرا را نگه دارید. برای متن فارسی، نقطه و ویرگول به واژهٔ پیش از خود می‌چسبند. جمله‌ها را در صورت طولانی یا مبهم‌بودن بشکنید، اما طول پاراگراف و تعداد تیترها معیار ثابت سئو نیستند. هر تیتر باید بخش واقعی خودش را توصیف کند.

## Gzip و HSTS

سرور Docker برای HTML عمومی، XML نقشهٔ سایت و دارایی‌های متنی، در صورت درخواست `Accept-Encoding: gzip`، پاسخ فشرده و `Vary: Accept-Encoding` می‌دهد. تصاویر فشردهٔ موجود، پنل، فرم‌های خصوصی و MCP از این مسیر عبور نمی‌کنند. پروکسی باید هدر `Accept-Encoding` را عبور دهد یا خودش برای محتوای عمومی فشرده‌سازی کند؛ از فشرده‌سازی دوبارهٔ پاسخ جلوگیری کنید.

پورت Docker فقط HTTP محلی است. **HSTS باید روی لایه‌ای که HTTPS عمومی را خاتمه می‌دهد فعال شود**، نه با اعتماد به `X-Forwarded-Proto` ارسالی از اینترنت. برای Nginx، پس از اطمینان از اعتبار گواهی، این خطوط را **در `server`های HTTPS موجود** قرار دهید و HTTP را جداگانه به HTTPS ریدایرکت کنید:

```nginx
# داخل server موجود روی HTTPS (نه بلوک HTTP)
add_header Strict-Transport-Security "max-age=31536000" always;
# اگر location خودش add_header دارد، هدر HSTS را آنجا هم اضافه کنید.
```

قبل از reload، `sudo nginx -t` را اجرا کنید. برای Caddy، `header Strict-Transport-Security "max-age=31536000"` را در بلوک دامنهٔ HTTPS قرار دهید. `includeSubDomains` یا `preload` را بدون بررسی تمام زیردامنه‌ها فعال نکنید. اگر TLS در CDN یا GitHub Pages خاتمه می‌یابد، هدر باید از همان سرویس مدیریت شود؛ برنامه نمی‌تواند هدرهای استقرار استاتیک را تعیین کند.

```bash
curl -fsSI -H 'Accept-Encoding: gzip' https://ominicorp.com/
curl -fsS --compressed https://ominicorp.com/en/blog
```

در پاسخ اول `Strict-Transport-Security`, `Content-Encoding: gzip` و `Vary: Accept-Encoding` را بررسی کنید (ممکن است CDN فشرده‌سازی دیگری ارائه دهد). پس از استقرار، نشانی‌های واقعی را در Rich Results Test و Search Console و پیش‌نمایش صفحه را در سرویس اشتراک‌گذاری بررسی کنید.
